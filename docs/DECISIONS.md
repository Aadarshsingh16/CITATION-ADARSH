# Decisions

Each row: what we chose, what we rejected, why, and the risk we accept.
Rows marked **OPEN** need the owner's decision before the related phase starts. Do not guess them.

| ID | Decision | Alternatives rejected | Reason | Risk accepted |
|---|---|---|---|---|
| D-001 | Next.js App Router + TypeScript + Tailwind | Separate React + FastAPI | Brief prefers Next.js, one deployable, shared `quotes.ts` between client and server | Long streaming on some hosts, handled by choosing a long-running host (D-003) |
| D-002 | Postgres + Drizzle, same engine locally and deployed | SQLite, JSON files | SQLite and local files do not persist on many hosts, and parity avoids deploy-only bugs | Slightly more setup (docker-compose) |
| D-003 | Deploy on Render (long-running Node web service + Render Postgres) | Railway, Vercel serverless | Streaming, 150-page ingestion and background jobs need long-running Node service; Render selected | Managed service configuration and spin-up time |
| D-004 | OpenAI-compatible client, config from `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | Provider-specific SDK | Brief requires env config and any provider; works with OpenRouter, Gemini, OpenAI | **OPEN: stays open until llm:check has run on two candidate models** |
| D-005 | One canonical text per document with page offsets | Re-extracting per feature, storing per-page text only | Makes multi-line and cross-page quotes tractable, one coordinate system for every feature | Extraction mistakes are baked in. Mitigated by a quality gate |
| D-006 | Single shared `quotes.ts` for verify and highlight | Separate server and client matchers | They can never disagree about where a quote is | Must stay free of server-only imports |
| D-007 | Strict matching after normalisation, no fuzzy fallback | Fuzzy or embedding similarity to rescue near-matches | A fuzzy matcher can verify a paraphrase, which the brief calls unacceptable | Rejects some genuine quotes the model slightly altered. Acceptable: shown as unverified, not hidden |
| D-008 | Whitespace-insensitive matching (strip all whitespace after normalising) | Collapse to single spaces only | Extraction can insert or drop spaces inside words ("Termi nation") | Tiny chance of matching across a word boundary, reduced by word-boundary check on the original text |
| D-009 | Word-boundary check on original text after a match | Plain substring | Stops a quote like "of the" matching inside "of theory" | Needs a careful definition for punctuation and digits |
| D-010 | Minimum quote length of 15 normalised characters | No minimum | Very short quotes match everywhere and prove nothing | A legitimately short quote (e.g. "Governing law") shows as unverified with reason `too_short` |
| D-011 | Ellipsis quotes verified as ordered segments within a bounded window, labelled "verified with gaps" | Reject any quote with "..." | Models often elide the middle of long clauses | Window size must be tuned, documented in EDGE_CASES |
| D-012 | Inline `<q id doc>` tags in the stream, verified when the tag closes | Trailing JSON citation block (as in the earlier citations project) | Works with streaming and Stop: verified quotes survive a stopped answer, an unclosed tag is dropped | Model may emit malformed tags. Parser is tolerant and drops what it cannot parse |
| D-013 | Unverified quotes shown with an amber badge and a reason, never hidden, never red | Delete them silently | Honest and debuggable, and matches the brief's "remove it or mark it clearly" | Reviewer sees some unverified items. That is the product working |
| D-014 | Ignore all model-reported pages and offsets | Trust page numbers to speed up lookup | Brief forbids it, models are unreliable at it | Slightly more matching work, negligible |
| D-015 | Allowlist of documents and chunks sent per request, quotes naming others are dropped and counted | Trust the `doc` attribute | The model must not be able to invent a source | None significant |
| D-016 | Misattributed quote (exists in another selected doc) is flagged `wrong_document`, not re-attributed | Auto-correct the doc | Silent correction hides model error and could attribute a clause to the wrong party | Slightly less convenient |
| D-017 | Coverage object on every answer, absence claims forbidden when `complete=false` | Rely on prompt wording alone | The brief's worst case is a confident "no such clause" after partial reading. Needs prompt and UI and code to agree | Extra bookkeeping in every mode |
| D-018 | Large docs: full / map-reduce / retrieval chosen by budget and question type | Single strategy | Map-reduce gives complete coverage for existence and "list all" questions, retrieval is cheaper for targeted ones | Map-reduce costs more calls. Concurrency and caching limit it |
| D-019 | Reduce step sees only verified candidate quotes | Reduce over raw map output | Fabrication cannot survive into the final answer | A good quote the verifier rejects is lost. Logged in telemetry |
| D-020 | BM25 for retrieval, embeddings only as an extra | Embeddings first | No extra provider or cost, deterministic, good enough for contract terms | Weaker on paraphrased queries |
| D-021 | Reject scanned PDFs at the quality gate, warn on partially unreadable | Silently save | Brief requires telling the user. Partial pages count against coverage | Threshold tuning (20 chars per page, 80 percent) may misjudge unusual files |
| D-022 | No OCR in core scope | Add OCR | Brief says tell the user, not solve it. Keeps the build fast | Scanned contracts are not usable. Possible later extra |
| D-023 | DOCX has virtual "sections" instead of pages | Fake page numbers | DOCX has no true pagination without rendering | Viewer and quote cards say "Section" for DOCX |
| D-024 | Superseded by D-034. Canonical-text viewer is kept for DOCX and as the fallback for PDFs | PDF.js only | See D-034 | See D-034 |
| D-025 | Part C: Option 2 (agentic research) | Option 1 (tracked-change redlining) | Reuses the verifier, retrieval and chunking, and has a clearer demo. Redlining needs deep OOXML work with high risk of a half-working result in 3 days | Judged as the "easier" option, offset by doing it well: caps, malformed-call handling, live trace |
| D-026 | Agent caps: 6 rounds, 12 tool calls, token budget, abort after 3 consecutive invalid calls | Uncapped or prompt-only limits | Brief requires a hard cap and no unbounded bill | An answer needing more lookups ends with a partial-coverage notice |
| D-027 | Invalid tool calls return a structured error to the model, never throw | Fail the request | Brief requires graceful handling, and the model can often self-correct | A model that never corrects wastes rounds, bounded by D-026 |
| D-028 | Comparison: clause alignment, deterministic signals, LLM only judges changed units | LLM diff of the whole documents, character diff | Brief forbids character diff, signals make numeric changes reliable, and cost is bounded | Alignment errors on heavily restructured contracts |
| D-029 | Significance levels: high, medium, low, cosmetic. Numeric, party, duration or modality changes raise it | Single score | Easy to filter and explain in the UI | Calibration is subjective, shown as guidance |
| D-030 | Status delivery to client: polling for ingestion, SSE for chat | All-SSE, all-polling | Polling is robust on any host for background file processing; SSE is optimal for token streaming | Polling incurs small delay (1s interval) |
| D-031 | Postgres bytea in a separate `document_files` table, 25MB cap | Mounted volume, object storage | Keeps local/deploy parity without external storage dependencies, separates large blob from documents table | DB storage grows with uploads |
| D-032 | Limits: 25MB file, 400 pages | No limits | Protects the service and keeps behaviour predictable | A larger legitimate contract is rejected with a clear message |
| D-033 | No auth, single user | n/a | Brief says so | Anyone with the URL sees all documents. State this in the README |

| D-034 | PDFs are shown as the real rendered page (pdf.js canvas + text layer) and highlights are mapped onto the text-layer spans. Canonical-text viewer remains for DOCX and as a per-page fallback | Canonical-text viewer only | The brief says the extracted text and the rendered page are laid out differently and the mapping "takes real work". Showing our own text view would dodge the requirement | Item order mismatch between extraction and render. Mitigated by pinning one `pdfjs-dist` version and falling back when item counts differ |
| D-035 | At extraction store, per page, the offset and length of every pdf.js text item inside the canonical text | Re-matching quotes against rendered spans at click time | Mapping becomes a range intersection, exact and fast, and multi-line, cross-page and repeated quotes fall out of the same code | Extra storage (about 1MB jsonb for 150 pages) |
| D-036 | One optional quote repair pass per answer: failed quotes are re-requested verbatim from the cited chunk and re-verified strictly | No retry | Cheap models paraphrase often, so honest answers would show many unverified quotes. Strict verification still decides | One extra call. The claim text is already streamed, so an unrepaired claim is shown as "no supporting quote" |
| D-037 | "Deep research" toggle in the composer enables agent mode, off by default | Agent mode always on, or automatic | Makes Part C visible and testable by a reviewer, and keeps the normal path fast and cheap | Reviewer might not find it. Add a hint and mention it in the README |
| D-038 | Model calls go through a tool-calling adapter. Native tool calls when the provider supports them, else a JSON action protocol in plain text | Native tool calling only | Cheap models and OpenAI-compatible gateways vary in tool-call quality | Two code paths, both covered by the same agent tests |
| D-039 | Per-IP rate limits and a global daily token ceiling from env, friendly message when hit | No limits | No auth plus a public URL means a stranger or a loop can spend our API key | A reviewer could hit a limit. Set generous defaults |
| D-040 | Stale-job sweep on server start (stuck documents become `failed` with Retry that re-runs from the stored raw file) | Full resumable job queue | Covers the "server restarts mid-job" case cheaply. A full queue stays an extra | A restart still interrupts the job, the user retries |
| D-041 | Comparison summaries are checked: every number, amount and date in a summary must appear in the clause texts or signals, else a templated summary from the signals replaces it | Trust the LLM summary | The headline feature must never invent an amount | Templated summaries read less nicely |
| D-042 | "Try with sample contracts" button seeds synthetic documents (a services agreement, a v2 with planted changes, a long 120+ page agreement) | Empty app on first load | A reviewer can exercise every feature in one click, and it protects against "only works on a small sample" because the long sample is real | Samples must be our own synthetic text, no real parties |
| D-043 | After P2, work splits into parallel tracks with file ownership (see PHASES.md) | Strictly sequential | Three days is tight and comparison, viewer and large-doc work are mostly independent | Merge conflicts, reduced by frozen shared types and `quotes.ts` |
| D-044 | Arabic hedge: NFKC handles Arabic presentation forms, `dir="auto"` in text blocks, ingestion never crashes on Arabic. Full RTL layout stays an extra | Ignore Arabic | The brief's AED example suggests UAE-style contracts, bilingual files are likely in a reviewer's hands | Visual-order extraction can break matching for Arabic. Documented as a limitation |
| D-045 | Rejected uploads (scanned, encrypted, wrong type) appear as dismissible error cards, not as library documents | Save as rejected rows in the list | Brief says never treat them as successful. A visible card explains what happened without cluttering the library | The reason is not kept after dismissal |
| D-046 | Duplicate upload allowed with a soft notice via sha256 hash | Reject duplicate, silent overwrite | Allows comparing different copies or re-testing without blocking, alerts user with notice | Stores duplicate file data |
